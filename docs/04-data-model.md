Source of truth for shape: `packages/shared/src/types.ts` (interfaces) and `schemas.ts` (zod). Server: `apps/api/prisma/schema.prisma`.
Mobile: `scaffold/mobile/src/db/schema.ts` (Drizzle).

`ResumeVersion`, `InterviewSession`, `InterviewTurn` and `SkillGap` are planned and not yet in the Prisma schema; add them in their stage.

## Rules from day one

- Identifiers are UUIDv7, generated by the client so records can be created offline.
- All times are UTC (epoch ms on the client, `DateTime` on the server).
- Every table has `createdAt`, `updatedAt` and `deletedAt` (soft delete) for sync.
- For a job we keep the raw text, the parsed JSON and the parser version, so parsing can be recomputed.
- A status change always writes an `ApplicationEvent`; history is append-only.

## Statuses and transitions

`saved -> applied -> hr_screen / tech_interview / test_task -> offer`, plus `rejected`, `ghosted` and `withdrawn`.
Full rules: `packages/shared/src/status.ts` (with tests). Terminal: offer (only -> withdrawn), rejected, withdrawn.
`ghosted` can be reopened if the recruiter replies. Nothing can move back to `saved`.
